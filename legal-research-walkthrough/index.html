This is a learning/training tool, not a real product — use a plain, original interface design (no real product branding, logos, or screenshots). TECH: A single self-contained index.html file with inline CSS and vanilla JavaScript. No frameworks, no build step, no external dependencies — it should open directly in a browser by double-clicking the file. STRUCTURE: A 6-step guided flow with a progress indicator (e.g. "Step 2 of 6") at the top and Back/Next buttons at the bottom. Each step is its own screen: 1. Frame the question — Show a vague research prompt (e.g. "client asks: can I be fired for refusing unsafe work?") and a short explanation of why turning a vague question into a specific legal issue is the first real skill in research. Include a simple mocked "issue statement" text box the user can type into (not validated, just for engagement). 2. Running the first search — Show a mocked search bar. Explain the difference between a natural-language search and a terms-and-connectors search, with a one-line example of each. Let the user click two tabs/toggles to see both example searches side by side. 3. Narrowing results — Show a mocked results list (5-6 fake case names, invented, not real) alongside mocked filter controls (jurisdiction dropdown, date range). Explain why narrowing too early can cause you to miss relevant authority, and why narrowing too late wastes time. Let the user toggle a filter and see the mocked list shrink. 4. Checking if a case is still good law — Explain the concept of a citator check (verifying a case hasn't been overturned or negatively treated) using a plain-language analogy. Show a mocked case card with a colored status flag (e.g. green "good law" vs. red "caution — negative treatment") and let the user click between two example cases to see the flag change. 5. Saving and organizing — Show a mocked "save to folder" interaction (a button that adds a fake case to a fake folder list on screen). Explain why organizing findings as you go saves time later. 6. Recap — A short summary screen listing the 5 skills covered, written as plain takeaways a new researcher could actually remember and use. STYLE: Clean, professional, neutral color palette (blues/grays), readable typography, generous whitespace — this should look and feel like a polished internal training tool, not a marketing page. Make sure text has good contrast and buttons are clearly clickable (this will be reviewed with an accessibility/UX eye). Each step should include a short "Why this matters" callout box separate from the main instructional text, so the teaching point is visually distinct from the interaction itself.
